# IRIS-Face 모듈 계약 v1 (콘센트)

Face 본체에 확장 모듈을 꽂는 규약. 본체는 모듈이 무엇인지 모른다 — 아래 계약만 지키면 어떤 모듈이든 꽂힌다. 2026-09-11 확정(설계 정본 = IRIS 메신저 P04 `docs\설계.md` 조각 1·7·8·10).

## 1. 자리와 파일
- 모듈 하나 = `modules\<이름>\` 폴더(Face 저장소 밖, `.gitignore`). 폴더 이름 = `module.json.name` = `^[a-z][a-z0-9-]{1,31}$`.
- `module.json`: `{ "name", "label", "icon", "version", "contract": 1, "grade": 0, "minFace": "2.47.0", "entry": "index.mjs" }`. `grade` 0 = 본체 정보 없음(v1이 실행하는 유일한 등급) / 1 = 세션 상태 읽기 / 2 = 세션에 요청 넣기(1·2는 동의 화면이 생기는 2차까지 싣지 않음).
- `icon` = 코어 아이콘 **이름**(Face 2.52부터, `app/icons.js`): `plug` `chat` `bell` `mail` `calendar` `globe` `book` `wrench` `clock` `folder` `bolt` `people`. 코어가 선 아이콘(SVG)으로 그린다. 목록에 없는 값(이모지 포함)은 `plug`로 보이며, 모듈이 준 문자열은 화면에 그대로 넣지 않는다.
- 모듈의 자기 저장 폴더 = `modules\<이름>\state\`(코어가 만들어 `hello.stateDir`로 알려 줌; 업데이트 설치 때 보존, 제거 때 삭제).
- 설치 zip: `module.json` · `entry` · `manifest.json`(파일별 SHA-256, `version: 1`, 선택 `source`) · `manifest.sig`(Ed25519, base64). 공식 = Face `daemon/modsign.mjs`의 공개 열쇠로 검증되는 서명. 서명 없음·불일치 = 비공식(설치는 사용자 명시 동의 뒤). **`manifest.json`은 비공식 zip도 필수**(없으면 서명 여부와 무관하게 설치 거부).
- 파일 지문 불일치·경로 탈출(`..`·절대경로) = 설치 거부. 그 밖의 항목 이름 거부 규칙: 예약 이름(대소문자 무시로 `con`·`prn`·`aux`·`nul`·`com1-9`·`lpt1-9`, 확장자 붙어도 해당) · `.`·공백으로 끝나는 경로 조각 · 콜론(`:`, ADS) 포함 조각 · zip 안에서 대소문자만 다른 중복 이름.
- 업로드·해제 상한: HTTP 업로드 50MB · zip 항목당 해제 64MB(`MAX_ENTRY_BYTES`) · zip 전체 해제 256MB(`MAX_TOTAL_BYTES`) · 항목 수 10000개(`MAX_ENTRIES`, `daemon/zip.mjs`). 선언된 크기·실제 해제 결과 양쪽을 검사해 압축 폭탄을 막는다.
- 모듈 설치·제거·재시작 라우트(`/api/modules/...`)는 **같은 출처(same-origin) 요청만** 받는다(`Origin`/`Sec-Fetch-Site` 검사) — 다른 로컬 웹페이지가 데몬을 대신 조작하는 것을 막는다.

## 2. 실행
- 코어(데몬)가 `node <entry>`를 **별 프로세스**로 띄운다(cwd = 모듈 폴더, 환경변수 `IRIS_MODULE_NAME`·`IRIS_MODULE_STATE`). stdin/stdout = 계약 전선(JSON 한 줄, UTF-8), stderr = 코어 로그.
- 죽으면 1초 뒤 재시작, 3회 넘으면 `failed`. `shutdown`을 받고 2초 안에 끝나지 않으면 그 PID만 종료.
- 계약 버전·`minFace`·이름 규칙·entry 존재가 맞지 않으면 싣지 않고 설정 화면에 이유만 보인다.

## 3. 말(허용 목록 — 이것이 전부)
| 방향 | 말 | 내용 |
|---|---|---|
| 코어→모듈 | `{"t":"hello","contract":1,"face":"<버전>","stateDir":"<절대경로>","lang":"ko","theme":{"id":"indigo","mode":"dark"}}` | 시작 직후 1회. 세션·폴더·기록·사용자 이름·이메일은 **주지 않는다** |
| 코어→모듈 | `{"t":"shutdown"}` | 끝내라 |
| 모듈→코어 | `{"t":"panel","url":"http://127.0.0.1:<포트>/..."}` | 화면 주소. 127.0.0.1 만 허용(300자 이하). 코어는 서랍 iframe으로 보여 준다 |
| 모듈→코어 | `{"t":"badge","count":<0..999>}` | 헤더 버튼 배지 |
| 모듈→코어 | `{"t":"notify","title":"<80자>","sub":"<120자>","target":"<120자>"}` | 화면 알림(창이 뒤면 OS 알림). 누르면 서랍이 열린다. 내용은 title·sub 뿐 |
| 모듈→코어 | `{"t":"queue",...}` | **v1은 받되 무시**(로그만). 2차 "사람 승인 대기열" 자리 |
그 밖의 말은 버리고 로그에 `dropped`로 남는다. **"세션에 글 넣기"는 계약에 없다.**

## 4. 화면
- 모듈 화면은 모듈 프로세스가 127.0.0.1 임의 포트에서 내놓는다. 주소에 1회용 토큰을 넣어 다른 프로그램의 접근을 막는 것을 권장.
- 코어 서랍 안 iframe에 그대로 들어간다. 모듈 안에서 Esc를 쓰지 말 것(코어가 서랍 닫기로 쓴다). 네이티브 `alert/confirm` 금지(초점 사고).
- 단축키: Ctrl+Shift+M = 첫 모듈 서랍 열기/닫기.

## 5. 약속과 한계
- 모듈이 하나도 없으면 Face는 127.0.0.1 밖으로 연결을 만들지 않는다(`npm run verify:nomodule`이 기계로 확인). **유일한 예외(Face 2.53 카탈로그):** 설정 → 모듈에서 사용자가 「설치」를 누른 그 순간에만 `daemon/catalog.json`에 적힌 GitHub 릴리스 주소(허용 호스트 = `api.github.com`·`github.com`·`*.githubusercontent.com`, https 만, 50MB 상한)로 zip 을 한 번 내려받아 같은 설치 길로 넣는다. 카탈로그 설치는 서명 검증을 통과한 공식 zip 만 받아들이며(비공식 동의 경로 없음), 화면을 열어 두는 것만으로는 아무 연결도 만들지 않는다.
- 카탈로그(`daemon/catalog.json`): `{ "version": 1, "modules": [ { "name", "label", "icon", "desc", "repo", "release": { "api": "<releases/latest>", "asset": "<zip 이름 정규식>" } } ] }`. 화면 목록 = 카탈로그 항목(설치됨/미설치) + 카탈로그 밖 설치 모듈. 설치된 모듈은 `module.json`의 label·icon 이 카탈로그 값보다 우선.
- 별 프로세스는 **버그 격리**이지 악의 격리가 아니다(같은 OS 사용자 권한). 악의 모듈 방어 = 서명(공식) + 사용자 동의(비공식).
- 검사: `npm run verify:modules`(호스트·zip·서명·설치) · `npm run verify:nomodule`.
